# Experiment 0008: OSU LoRa relation-split feasibility v0

## Hypothesis

The current OSU LoRa observation-oracle contract cannot support a leakage-safe
train/calibration/validation/test assignment because it does not observe a
session axis; a bounded split compiler will fail closed instead of substituting
setup, day, domain, or path structure for session evidence.

## Method

Pre-implementation base revision: `42ec585`.

The compiler consumes the ignored aggregate oracle generated by:

```sh
just osu-lora-profile
just osu-lora-oracles
```

It attempts a deterministic four-role assignment, validates the candidate with
the existing `netbraid.relation_split_manifest.v2` parser and auditor, and
requires event and session separation across every role pair. The compiler may
use only declared opaque group identifiers. It may not infer a session from a
domain, setup, day, receiver, location, configuration, source path, or input
order.

The hermetic contract is:

```sh
just osu-lora-relation-split-check
```

The real-corpus feasibility run is:

```sh
just osu-lora-relation-split
```

A successful split must assign every observation exactly once, keep alternate
representations of one event together, contain all six forbidden cross-role
axis intersections, and produce a byte-identical canonical manifest under
input-order changes. A blocked run must return the stable
`unbounded_session_axis` reason and publish no split manifest.

## Data provenance

The input is the ignored `data/derived/eval/osu-lora-observation-oracles.json`
produced from publisher SigMF metadata and local fetch receipts. It contains
domain-separated opaque group identifiers and aggregate provenance, not IQ or
FFT payloads, publisher paths, source URLs, device labels, or local paths. The
split compiler does not open waveform payloads.

## Results

Not executed. The full OSU LoRa acquisition and fresh oracle compilation are
still in progress.

## Conclusion

Pending. If the registered blocker is observed, the next experiment must first
establish a documented conservative session-containment group or choose a
corpus with explicit sessions; relaxing the split policy is not an acceptable
workaround.
